# 踩坑记录

按遇到顺序记录。每条都是"现象 → 根因 → 解决"，不是教程，是排查过程。

## 1. chromadb 在 Windows 上写入直接崩

**现象**：建库到写入阶段，进程无输出退出，退出码不是异常而是段错误；换 collection 名、删目录重建都复现。

**根因**：`chromadb==1.0.20` 的 Rust 内核与 Python 3.13 + Windows 的组合不兼容，问题不在我们的调用方式。

**解决**：实现双后端，`simple` 用 numpy 算余弦，首次建库时自检写入 `data/backend_decision.json`，后续自动选择。功能一致，省掉一个原生依赖。

## 2. qwen3 的思考把答案吃掉

**现象**：回答里全是"让我想想……用户问的是……"这类过程文字，最后没有结论。

**根因**：thinking 模式一直写到 `num_predict` 用尽，没有结束标记，模型把整段思考当正文吐出。

**解决**：`num_ctx=8192`、`num_predict=4096` 给思考留空间，同时在用户消息尾部加 `/no_think`。换非 qwen3 模型要关掉这个标记。

## 3. 启动脚本中文乱码，整个 if 块被拆散

**现象**：双击 bat 窗口一闪而过，服务根本没起。

**根因**：脚本存成了 UTF-8，而 cmd 默认代码页是 936（GBK），中文字节被误读成乱码，`if (...)` 的括号配对被打断。

**解决**：重写脚本为 **GBK + CRLF + 全绝对路径**，并在 README 里写明"改这个文件必须保持编码"。

## 4. Open WebUI 起不来：torch 的 DLL 加载失败

**现象**：`OSError: [WinError 126] ... torch\lib\shm.dll or one of its dependencies`，重装 torch 无效。

**排查**：用 `pefile` 读 `torch_cpu.dll` 的导入表，逐个 LoadLibrary 试，发现唯一失败项是 **`VCRUNTIME140_THREADS.dll`**——系统里只有 VS2019 的 14.29 运行时，缺 VS2022 才有的这个。

**解决**：从 Ollama 自带的库里拷一份到 `torch\lib\`：

```
C:\Users\<user>\AppData\Local\Programs\Ollama\lib\ollama\cuda_v12\vcruntime140_threads.dll
→ .venv\Lib\site-packages\torch\lib\
```

重装 torch 会覆盖，需要重新拷。之所以不装 VC++ 运行库，是因为当时没有管理员权限，且单文件拷贝作用域更小。

## 5. Open WebUI 偷偷把 RAG 链路跑了两遍

**现象**：一轮问答 8 分钟。审计日志多出一条 `### Task: Generate a concise title summarizing the chat history.`，`route=reject`，耗时 200+ 秒。

**根因**：Open WebUI 开新会话时会让"当前模型"顺手生成标题，这个请求走的是同一个 OpenAI 兼容接口，因此也进了完整 RAG：检索、路由、模型，全跑一遍，还和正文抢 Ollama。

**解决**：在兼容层加 `_oa_task_reply()`，识别 `### Task:` 开头的请求直接返回（标题任务取对话首句前 16 字），实测 **0.14 秒**，不再进 RAG。改环境变量 `ENABLE_TITLE_GENERATION=false` 没用——那项只在首次初始化时写进数据库，之后以库里的配置为准。

## 6. Open WebUI 装不上：Python 版本被卡

**现象**：`pip install open-webui` 解析失败，要求 `<3.13`，本机只有 3.13.18。

**解决**：用 `uv` 单独建一个 3.12 环境：

```bash
set UV_PYTHON_INSTALL_MIRROR=https://mirror.nju.edu.cn/github-release/astral-sh/python-build-standalone
uv venv --python 3.12 .venv
```

官方 GitHub Release 下载慢，换南大镜像后 21 MB 几十秒下完。

## 7. 官方 PyPI 不通

**现象**：`pip install` 卡在解析，`https://pypi.org` 直接超时。

**解决**：统一走清华源 `https://pypi.tuna.tsinghua.edu.cn/simple`（`uv` 用 `UV_DEFAULT_INDEX`）。测试过阿里、腾讯源均可，选清华是因为当时返回最快。

## 8. 想装 Dify，被内存劝退

**现象**：Dify 需要 4~6 GB 常驻，而本机可用内存只有 3 GB（Ollama 已占 3 GB）。

**结论**：能装不能测。改走 Open WebUI 的 pip 方案：无 Docker、常驻约 0.7 GB。这笔账算下来，"功能完整但跑不动"不如"功能刚好且能跑"。

## 9. 微信接不了，改飞书（顺带否掉）

**事实**：微信公众号要求 5 秒内响应，否则重试 3 次、用户看到"暂时无法提供服务"；客服消息还有 48 小时 5 条的限制。本机一轮问答 4~9 分钟，直接出局。

**替代**：飞书自建应用的长连接模式不需要公网 IP、不需要内网穿透，3 秒内 ack 即可，后台慢慢算再推消息。如果以后要做办公入口，走飞书而不是微信。

## 10. PowerShell 会话里调不到系统命令

**现象**：脚本里调 `netstat`、`findstr`、`wsl` 报"不是内部或外部命令"。

**根因**：这个执行环境的 `PATH` 没带 `System32`。

**解决**：一律写绝对路径，如 `C:\Windows\System32\netstat.exe`。另外 `$PID` 是只读变量，做进程管理要换变量名（`$srvPid`）。
