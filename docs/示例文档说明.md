# 示例文档说明

`demo_docs/` 里的文档**全部为虚构内容**，公司名（辰星科技）、人员、数字均为演示用途，不对应任何真实企业。可以随意替换成你自己的资料。

> 这份说明刻意放在 `docs/` 而不是 `demo_docs/`：建库时会把目录下所有 `.md/.txt/.pdf/.docx` 都当成资料，说明文件放进去会被索引成"制度条款"。

## 现有文档（8 份）

| 文件 | 演示点 |
|---|---|
| 辰星科技员工手册.txt | 总纲，其余制度都引用它 |
| 费用报销管理规范.txt | 按岗位分档（职能岗 / 技术岗 / 市场岗），需要跨文档取条件 |
| 考勤、加班、休假管理办法.txt | 年假档位规则 + 具体天数，需要做数值计算 |
| 入职转正离职办理流程.txt | 流程类问答，多步骤 |
| 社保公积金缴纳说明.txt | 比例、基数类问答，容易出数值错误 |
| 竞业与保密协议摘要.txt | 含「仅限核心岗位」这类限定，最容易答错，适合测检索精度 |
| 采购管理办法.md | 金额分档表格 + 「不得拆分规避」这类反向约束 |
| 用章与合同签署流程.md | 多印章、多审批人，适合测多条件叠加 |

## 换成自己的资料

把 `RAG_DOCS_DIR` 指向目标目录即可（支持 `.txt` `.md` `.pdf` `.docx`），然后重建：

```bash
python -m app.rag.build --rebuild
```
